## One-time build and smoke checks

- Rebuild production PTX/shared library separately before timing:
  `make -C src/pdcs_gpu/cuda rebuild-gpu CUDA_HOME=<toolkit> ARCH=<gpu-arch>`.
- Re-run the smoke suite after any CUDA source or solver-policy change.

## Experiment 1: vector-vector reduction counts

- Cover SOC dimensions 3, 10, 100, 1,000, and at least one application-scale
  dimension; cover primal and dual EXP cones (dimension 3).
- For each case run the ordinary projection code and the genuinely diagonal
  projection code on identical inputs and seeds.
- Confirm `projection_events` equals the actual number of structured-cone
  calls. With `scope=:pdhg_iterations`, verify it equals the sum of primal and
  dual structured cones over all counted PDHG steps. Do not use
  `oracle_evaluations` as the vector-work count.
- Repeat one short run with `scope=:all` and confirm the difference is exactly
  the projection events introduced by termination/restart/infeasibility checks.
- Manually audit a small SOC case: ordinary SOC has one norm reduction on its
  normal path; every executed `nrm2`, `nrm2_squared`, or `diff_norm` adds one.
- Manually audit one EXP path: each three-coordinate distance/dot reduction
  adds one; scalar root-oracle arithmetic does not.
- Generate the experiment-1 table with
  `benchmark/R3.5_projection_work_profile.jl`.
- Repeat the final timing with profiling disabled and production PTX loaded.

## Experiment 3: projection tolerance

- Run fixed (`adaptive_projection_tolerance=false`) and adaptive (`true`) from
  identical data, initial points, seeds, and all other solver options.
- Verify fixed tolerance remains exactly `1e-12`.
- Verify adaptive starts at `1e-7`, is monotone non-increasing, and never drops
  below `1e-14`.
- Run the omitted/default mode and verify it reproduces the legacy tolerance
  trace and termination result.
- Record actual projection events, total vector-vector reductions, reductions
  per event, PDHG iterations, projection time, solve time, and final KKT.
- Compare work/time only when fixed and adaptive runs meet the same final KKT
  termination target.

## Experiment 4: no/diagonal/scalar-cone rescaling

- No scaling: `rescaling_method=:none`.
- Diagonal: `rescaling_method=:ruiz_pock_chambolle` and
  `scalar_cone_rescaling=false`.
- Scalar cone: either `scalar_cone_rescaling=true` with the same method, or
  `rescaling_method=:ruiz_pock_chambolle_scalar_cone`; verify equivalence.
- Also smoke-test the Boolean option with `:ruiz` and `:pock_chambolle` alone.
- After every Ruiz round and after Pock--Chambolle, check max/min cumulative
  scaling agree within floating tolerance inside every SOC/RSOC/EXP block.
- Confirm non-conic/free/nonnegative coordinates retain their original
  coordinate-wise rescaling behavior.
- Confirm constant-scale dispatch codes use ordinary projections:
  SOC `21/7`, RSOC `24/10`, primal EXP `26/28`, dual EXP `11/14`; genuine
  diagonal blocks must keep `22/25/27/29` and `6/9/12/15` as applicable.
- Compare restored solutions and final KKT conditions across all three modes.
- Run warm-start, zero-entry row/column, multiple-cone, mixed-cone, and a large
  SOC case to catch indexing and reduction errors.
- Run the three paper applications with identical seeds/options and report
  preprocessing time, projection time/work, PDHG iterations, total time, and
  final KKT.
