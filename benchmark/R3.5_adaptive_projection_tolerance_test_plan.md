# Adaptive projection tolerance：待执行测试清单

> 当前没有 idle GPU。本文件只记录测试范围和通过标准；在 GPU 可用前不执行。

## 配置方式

直接 API：

```julia
PDCS_GPU.rpdhg_gpu_solve(
    # problem data ...
    adaptive_projection_tolerance = true,  # false 或 nothing
)
```

JuMP/MOI：

```julia
set_optimizer_attribute(
    model,
    "adaptive_projection_tolerance",
    true,  # false 或 nothing
)
```

## 1. 纯策略单元测试

测试文件：`test/test_adaptive_projection_tolerance.jl`

- `adaptive_projection_tolerance = true`
  - 初始化 `proj_abs_tol = proj_rel_tol = 1e-7`；
  - 平均 KKT error 从 `1`、`1e-1`、`1e-4` 下降时，tolerance 分别为
    `1e-7`、`1e-8`、`1e-11`；
  - tolerance 只能收紧，KKT error 暂时变差时不能重新放宽；
  - 正常更新和 step-size stall safeguard 都不能低于 `1e-14`。
- `adaptive_projection_tolerance = false`
  - 初始化为 `1e-12`；
  - 对所有 KKT error 均保持 `1e-12`；
  - step-size stall safeguard 也不能改变该值。
- `adaptive_projection_tolerance = nothing`
  - 初始化仍为 `1e-11`，`proj_base_tol` 仍为 `1e-9`；
  - 对多组 current tolerance 和 KKT error，逐项验证结果等于修改前的公式；
  - stall safeguard 仍使用修改前的 `1e-22` 下限。
- API 存储
  - `PDCS_GPU_Solver` 正确保留三态值；
  - MOI `RawOptimizerAttribute("adaptive_projection_tolerance")` 可 set/get。

## 2. API 贯通测试

分别对 `true`、`false`、`nothing` 执行以下入口：

1. `PDCS_GPU.rpdhg_gpu_solve`（CPU 输入）；
2. `PDCS_GPU.rpdhg_gpu_solve_input_gpu_data`（GPU 输入）；
3. `PDCS_GPU.solve_with_solver(PDCS_GPU_Solver(...))`；
4. `PDCS_GPU.Optimizer` 的 MOI/JuMP 入口；
5. 完全不传该选项，确认等价于显式传入 `nothing`。

通过标准：所有入口均把相同三态值写入 `sol.params.adaptive_projection_tolerance`，
且第一次 projection 使用与该模式对应的初始 tolerance。

## 3. GPU projection kernel 覆盖

每种模式至少覆盖以下 cone/path：

- 未缩放 SOC 显式投影；
- diagonal SOC root search；
- 未缩放 rotated SOC；
- diagonal rotated SOC root search；
- primal exponential cone；
- dual exponential cone；
- diagonal primal/dual exponential cone；
- thread-wise、block-wise、warp-wise 和 grid-wise projection dispatch。

通过标准：无 kernel launch error、非法内存访问或 NaN；fixed 模式的每次
root-search 调用均收到 `1e-12`；adaptive 模式收到的 tolerance 位于
`[1e-14, 1e-7]` 且随求解过程单调不增；legacy 模式与原行为一致。

## 4. Legacy 回归

在修改前的 commit 和新代码的 `nothing` 模式上，使用相同 GPU、seed、输入、
初始点和参数运行：

- 一个 SOC hard case；
- 一个 exponential-cone hard case；
- Fisher market 代表实例；
- Lasso 代表实例；
- Multi-period portfolio 代表实例。

逐项比较：exit status、PDHG iterations、restart 次数、最终 objective、primal
error、dual error、relative gap 和恢复后的解。确定性运行应逐项一致；若底层
GPU reduction 存在非确定性，则数值差异必须在既有回归阈值内。

## 5. Fixed 与 adaptive 正确性

对相同问题、seed、初始点、scaling 和 termination tolerance 分别运行：

- `false`：fixed `1e-12`；
- `true`：`1e-7 -> 1e-14`；
- `nothing`：legacy。

三组都必须达到相同的最终 KKT 终止条件。记录：

- tolerance history；
- PDHG iterations；
- projection 调用数与向量乘法总次数；
- projection GPU 时间；
- 总求解时间；
- 最终 primal error、dual error、relative gap。

## 6. 边界与异常测试

- KKT error 为 `Inf`、大于 `1`、等于 `1`、接近零和等于零；
- 已经收紧后 KKT error 反弹；
- 求解在第一次 termination check 结束；
- `check_terminate_freq != print_freq`；
- 触发 step-size stall safeguard；
- `use_adaptive_step = false`，确认它不改变 projection-tolerance policy；
- `use_preconditioner = false` 和 `rescaling_method = :none`；
- 非法选项值（例如字符串）应在有类型约束的直接 API 入口被拒绝。

## 7. 建议执行顺序

GPU 可用后依次执行：

1. 纯策略单元测试；
2. 小规模 SOC/EXP GPU smoke tests；
3. 四种 projection dispatch 覆盖；
4. legacy 回归；
5. 三类论文应用的 fixed/adaptive/legacy 对照。

任何性能结论都只使用未插桩 kernel；插桩版本仅用于调用次数和 tolerance
history 的正确性核验。
